# KV6 model review

1. Confirmed stale cached lists on `voxlap_models` changes. Current `glx_displaylist_draw` checks the recorded type and refuses mismatched draws, so the observed result can be missing models and warnings rather than garbled vertices. Each model now tracks the list's point/mesh format and greedy setting, invalidating lazily when needed. This includes separately cached skin previews, not just the global models. A greedy change while using points does not rebuild an unaffected point list; switching back to mesh does.
2, 13. The per-row VLA could use roughly 512 KiB at the allowed maximum axis size. It was allocated during list construction, not necessarily every frame. A single heap scratch buffer is now shared by all greedy faces in one mesh build; allocation failure releases the other workspace and leaves the list unbuilt for a later retry. No arbitrary dimension limit was added, preserving existing high-resolution assets.
3. Both validation and decoding use readers with signed-int indices. Validation now rejects an exclusive table end above `INT_MAX` before reading the table or decoding; this also bounds every voxel-record offset and the readers' internal additions. Point-array indexing also now uses `size_t` multiplication. This is a format size limit, not full resource-exhaustion protection against very large but valid files.
4. Dimension rejection now invalidates any uploaded list and frees the voxel allocation, so model counts and future reloads see an empty model.
5. The only current decoder caller is `kv6_reload`, which validates first, invalidates and frees the previous resources, and sets the pointer to NULL. On malformed input the public unsized decoder cannot safely inspect arbitrary bytes; simply setting a pre-existing pointer to NULL would leak ownership rather than fix it. Its no-owned-resources/validated-data contract is documented; callers should use `kv6_reload`, which preserves the previous model on failure.
6, 7, 19. The spectator-to-2 remap was redundant: both 255 and 2 go through the default switch today. It is removed. Only black/team-colored voxels receive the default black team tint; explicitly colored voxels do not become solid black.
8. Both paths reset the shader team tint after drawing; documented at the reset. Compatibility rendering also has fixed-function color state, so this is not a general guarantee about every GL state.
9. `glx_shader` itself returns `int`, and the project uses signed handles elsewhere. A local GLuint conversion would not fix the API-wide representation issue. Deferred broader GL handle API change.
10. `glx_shader` already logs compile/link errors and returns zero. On the non-programmable compatibility path, a failed point shader now uses the existing fixed-function point setup rather than uploading uniforms to program zero. Core already has a one-pixel default-shader fallback. Actual driver behavior, including fallback point sizing, requires runtime testing; programmable non-Core fallback is not changed.
11. One byte stores all six face flags per voxel; a 5,000-voxel bit-packed six-bit representation would take about 3,750 bytes, not 625. The simpler byte representation remains.
12. Empty team tessellators do allocate initial CPU storage, and black voxels are the team-color partition. The split is necessary for team tinting; optimizing empty buffers is deferred pending profiling and backend validation.
14. Flipped models do extra matrix uploads. Avoiding them requires confirming the matrix/uniform and fixed-function state dependencies in both renderers; deferred without profiling or GPU tests.
15. `kv6_rebuild_complete` invalidates the listed global models for lazy recreation. Per-model setting tracking also covers skin previews. Renaming the established API is cosmetic and deferred.
16. Moved the two point shader source pairs to file-scope constants with their existing conditional compilation. The shader text is unchanged; mesh/default shader lives in `glx.c`.
17. The claimed flashlight formula mismatch is not present: world/default shaders first compute `fill = 0.30 * fill * fill * range`, so their `range + fill` equals the KV6 shaders' `range + fill * range`. The corresponding spotlight formulas are also algebraically equivalent. A cross-reference was added; sharing snippets is a larger GLSL/backend refactor and remains desirable.
18. The face mask name is generic but its use is local. Renaming is deferred to avoid mixing mechanical churn into the fix.
20. The multisample setting is tested twice but is not a saved copy of GL state. Caching the config value would not restore the actual previous GL enable state; state-preserving changes need backend testing.
21. Invalid data already logs `Invalid KV6 model: <path>` in addition to the generic load failure; missing/unreadable data currently gets only the generic message. Making missing built-in files fatal would change existing optional/fallback behavior. More granular load errors are deferred.
22. Point size is subject to driver limits; noted in the source. Core enables programmable point size and the compatibility shader path does likewise, with platform-dependent behavior.

## Verification and limitations

All 89 Python regression scripts passed. Extracted production C tests exercise model cache format/greedy transitions including a preview, maximum-axis greedy scratch and partial-row rollback, oversized file-header rejection before table access, existing valid assets and reload ownership. Shader extraction was checked against the original string literals. Model source syntax was checked for Core and legacy using incomplete GL/cglm stubs with extra constant definitions; those checks are not real OpenGL builds. No desktop/mobile driver, GPU, interactive setting toggle, shader-failure fallback or visual flashlight test was available.
