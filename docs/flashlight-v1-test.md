# Testing Flashlight V1

This client implements [zerospades/aosprotocol `extensions/flashlight.md`](https://github.com/zerospades/aosprotocol/blob/master/extensions/flashlight.md), merged from PR #9. It does not implement a server. A test server must implement/offer extension **0x32, version 1** and packet **0x72**, and relay accepted client Light requests. The existing `Enable flashlights for all players` option is a legacy-server approximation and is ignored when this extension is negotiated.

1. Build/run a client with **Dynamic lights** enabled. Connect to a server that advertises `0x32` in Extension Info (packet `0x3c`); check the client log for the offer and the v1 reply. Run `python3 tests/flashlight_protocol_test.py`, `python3 tests/teamplay_negotiation_test.py`, and `python3 tests/flashlight_integration_test.py` for repeatable wire/lifecycle checks without a server.
2. With player ID `0` as an example, a server can send `72 02 ff 3c 5a ff b3 80 00` (default for every unconfigured player: 60-block reach, cone `0x5a`, warm RGB, no flicker), then `72 00 00 01` to turn player 0 on. The Cone byte is in `pi/256`, so `0x80` is a 90-degree beam and `0xff` is about 179.3 degrees; neither is clamped. The trailing Flicker byte is `0` for a steady light; a server built before it existed may send the eight-byte packet without it, and the beam is then steady. A joining client can receive `72 01 01` **after State Data** to initialize that state. These examples are complete hex packets including top-level ID; when calling `network_send`, pass only the bytes after `72`.
3. Press **F** while alive in first person. With extension negotiation, the client sends `72 00 00 00` if its currently confirmed light is on, or `72 00 00 01` if off. The client does **not** change the light until the server broadcasts a Light response. Try refusing a request and confirm it stays unchanged; try sending Light for a teammate and enemy and confirm their lamps follow their rendered facing, regardless of the legacy all-player setting.
4. Send `72 02 00 14 1e 00 ff 00 00` to configure player 0 with a short green beam (20 blocks, cone `0x1e`). Send `72 02 00 00 00 ff ff ff 00` for a zero beam: no projected light, even when its on bit is set. Flicker is `Flicker/512` of the time dark, in short irregular bursts, and the beam and its lamp glare drop out together: `72 02 00 3c 80 ff ff ff c0` drops out about 3/8 of the time. Change the default config with player ID `ff`: an existing personal override must remain intact.
5. Confirm the light a server has not switched on is never drawn, the client's own included. Confirm **Create Player / Kill Action** switch only that player's light off; **Player Left** also clears its personal beam; **Map Start** clears every on bit but preserves beam configurations. Disconnect and reconnect: all bits and configurations reset. Without extension negotiation, F and the old optional all-player approximation continue working locally; no packet `0x72` should be sent.

The renderer selects at most four relevant lights per frame, including the local beam, so on a busy scene farther sources may have a visible tip but no projected illumination. A live server/GPU test is required to validate appearance and actual relay behavior; the included C harnesses verify only the client protocol and source wiring.
