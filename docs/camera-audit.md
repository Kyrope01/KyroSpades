# Camera review

## Fixed

- The ADS calculation mixed degrees and radians. We retained the existing apparent 2x optical-zoom intent (the existing tangent formula divided by two), but now convert radians to degrees. The setting labels previously suggested the input was the final FOV; their help text now calls it the base FOV for 2x zoom. This changes existing visual zoom: the default base of 70 degrees yields about 38.6 degrees instead of about 47.1. It needs in-game feedback, especially for custom sights and saved settings.
- Scope animation now follows the same sprint and delay gates as camera ADS; HUD visibility uses its progress rather than raw RMB. Sprint FOV smoothing now uses an exponential time-based coefficient; the old `5*dt` was already approximately time-based, not 3 frames at 30 Hz versus 24 frames at 240 Hz as claimed, but its convergence varied with timestep. Invalid frame deltas are rejected.
- An invalid `int` passed to `camera_hit_fromplayer` produces a fully initialized no-hit result. Hit results are initialized; terrain and player hits are accepted by their actual world-space distance, not their origin/corner distance. The old point prefilters could reject a hitbox/face within reach. A scaled player's model-space intersection distance is converted to world-space distance. Hit-test terrain traversal now uses the caller's range, including beyond 128 units; ordinary placement/picking keeps the existing 128-unit cap.
- Free-aim at a pitch pole now allows the camera to catch up when the crosshair is pinned; the poles use `PI - EPSILON`, with an accurate angle convention comment. This affects the feel near straight up/down and needs playtesting.
- The inside-block pass saves and restores model matrix, depth function/write mask, culling, blending and applicable fixed-function texture enable state. It restores the previous shader program on programmable contexts. GLES2 avoids invalid fixed-function texture-enable calls.

## Qualifications and deferred work

- `local_player_id` is an unsigned byte and `PLAYERS_MAX` is 256, so negative or out-of-range local array access as described is not possible in this revision. ID 255 is still used as a server/sentinel elsewhere; semantic pre-join validity is a separate concern and zeroing the eye position would silently change callers.
- `matrix_multiply(m,n)` premultiplies `n*m`; frustum extraction therefore produces `P*V*M`, matching `matrix_upload`. A box enclosing the frustum cannot have all eight corners outside a single inward-facing frustum plane, so the proposed large-box false-cull explanation is incorrect. Boundary precision and degenerate matrices remain separate test topics.
- At pitch zero the direction is `(0, 1, 0)`, not a zero vector. Water is rendered separately; the review did not establish that `map_isair` treats water as a solid voxel.
- The inside-block loop checks geometry bounds before calling `map_isair`, so it does not normally make 27 map calls. Caching by voxel alone is unsafe when the camera moves within the margin or blocks change; map revisions and profiling are needed first. The underlying tessellator still has its own client-array/shader-state conventions; restoring all GL state was not established by this change.
- Removing the unsafe player-origin prefilter may increase hitbox work, including sound probes. A conservative bound must cover animation, scaled hitboxes and authoritative/interpolated position before reintroducing a broad phase; benchmark it rather than using an unverified radius. The proposed projection test assumes normalized rays and an unspecified hit radius. No FPS gain is claimed.
- Fixed 128-unit cap remains in public terrain picking; no server-configured extended placement reach was found. No reach policy was changed. Matrix/frustum and renderer performance need profiling on real hardware. Native gameplay, GPU and Android tests were unavailable; automated tests use extracted production code and fake GL.
