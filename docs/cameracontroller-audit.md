# Camera-controller review

## Changes

- Death-camera initialization uses a finite, nonzero direction check and zero velocity when positions coincide. Its velocities are updated for the sound listener during death motion. Coincident positions no longer inject NaNs; transition out of death mode still depends on the existing collision/settling logic, which is not guaranteed without terrain.
- Grounded crouch changes physical position by the full 0.9 units once in both settings modes. The old non-instant branch applied a frame-dependent fraction and never applied the remainder, while uncrouching could restore a full 0.9. The existing `crouch_instant` config key is retained, but now controls camera easing only; the menu calls it “Smooth crouch camera.” Smoothing is exponential and independent of the dynamic-FOV setting. Uncrouching compensates for the *actual* eye displacement, avoiding an artificial camera jump on a midair uncrouch. These are gameplay-feel changes that need multiplayer testing.
- The bodyview scan keeps its original 0.05-unit samples and geometry but no longer casts again in a direction whose answer is already known; constant angles and player height are computed once. An empty-air test goes from roughly 200 to roughly 100 terrain queries. This is a measured call-count reduction, not an FPS benchmark.
- Removed redundant selection update-time matrix operations (the view is reset before the render pass). Guarded FPS and spectator-bodyview direction normalization against zero lengths, and made the FPS controller tolerate a null HUD. Removed an empty conditional and moved the existing network function declaration to its header include.

## Qualifications

- `local_player_id` is an unsigned byte and the player array contains 256 entries; the claimed negative/out-of-range access from this ID is impossible in this revision. Server/sentinel ID 255 and validity of the current session are separate concerns.
- The chat/menu mask preserves **crouch**, not sprint: player input bits are up, down, left, right, jump, crouch, sneak, sprint. The reported repeated sinking mechanism doesn't occur via that mask. The actual crouch branch contained a separate timestep bug. The main loop clears movement before the fixed physics tick when a menu covers a connected game.
- Midair crouch switches the collision shape without shifting the feet; `player_boxclipmove` applies crouched collision geometry during the subsequent fall. An unconditional 0.9 shift on landing could put a player into terrain, so the proposed landing adjustment was not added without server parity and playtests.
- First-person spectating is explicitly selected via `cameracontroller_bodyview_mode`; its eye-position override is intentional. The finite player search is bounded to 256 iterations. Holding jump currently re-requests a jump after landing; this behavior was not redesigned.
- Coarse 0.25-unit scan steps can skip thin/intermittent obstructions, so the suggested coarse search was not used. A correct swept AABB or conservative broad phase could improve this further but needs differential tests and profiling. Caching spectator basis and replacing `powf` were not assumed to improve performance without measurement. Roll handedness, other camera state reset, sound velocity unit conventions and complete HUD lifetime remain follow-up topics.
- Tests exercise extracted production code using simulated collision/player state: coincident death position, crouch/release and blocked uncrouch, midair input, and 2,000 comparisons to the previous bodyview scan. They do not replace an in-game multiplayer, GPU or Android test; no native full build was available.
