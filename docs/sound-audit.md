# sound.c review

## Findings and changes

1. Sticky creation now rejects null players and IDs outside `0..PLAYERS_MAX-1`; update detaches an invalid stored positive ID before any access. The reported network exploit is not established in this checkout: network player IDs are bytes and `players` has 256 slots, including the server pseudo-player. The public API takes an `int`, however, so the defensive check is warranted.
2–3, 17. Added `camera_hit_terrain`, sharing the existing terrain intersection implementation without iterating or allowing players to mask block hits. Occlusion and room probes use it. The actual loop has **256** slots, not 32. This removes player collision work but does not eliminate the 27 terrain casts on source creation. We retained the immediate probe: deferring it for four staggered frames can leave short gunshots/footsteps partially unoccluded or muffled throughout their lifetime. A scheduling change should be profiled and listening-tested before adoption. Terrain-only behavior deliberately means players no longer occlude room/sound rays; validate in play.
4–5. All eleven EFX entry points, including auxiliary-slot deletion, are required before use. Errors at effect allocation, effect type, slot allocation and attachment clean up any acquired IDs. Normal shutdown deletes sources/filters, slot and effect, then releases the OpenAL context/device. Context-creation failures also close resources. Tested with fake procedures; real driver/context lifecycle remains unverified.
6. Rain only enters the playing state after successful source creation and play; partial setup is cleaned up.
7. `camera_terrain_pick_range` normalizes internally and `aabb_intersection_ray` returns **world distance**, even with non-unit input. The report's ray-parameter explanation is incorrect for this implementation. Each grid ray now uses its own actual distance to the listener, rather than the central ray's distance. The under-one-unit no-occlusion policy is preserved; it can ignore a very close wall.
8. Sticky position updates remain before probes and are documented. 9. Source cleanup zeroes both source and filter IDs; stolen entities are still reaped on the next update.
10, 12, 13. Both mono and stereo decoded buffers leaked in `sound_load`; mono also leaked in `sound_reload`. A shared uploader frees all decoded and mixed data, checks size/rate/channel bounds and OpenAL allocation/upload errors, uses size-safe counters, and preserves the existing buffer when a reload cannot be decoded or uploaded. Missing startup sounds now warn and stay silent rather than terminating the game; creation ignores null/empty sounds.
11. The bundled `src/dr_wav.c` is an older API returning **interleaved sample count**, not frames. A real one-second 8 kHz stereo fixture returns 16,000 samples and now uploads 8,000 mono frames. The proposed frame-count fix would be wrong for this copy. More-than-two-channel inputs previously combined the first half as stereo and truncated; the uploader now averages all channels in each frame. This is a simple equal-weight mix, not a surround-channel-aware downmix.
14. Filter creation and configuration errors fall back to an unfiltered source and clean up acquired filters. 15. Listener-up math is unchanged; horizontal pitch is π/2. 16. Direct entity buffer traversal is retained for now; `entitysys_iterate` currently also exposes and compacts entries and has no destructor facility. Do not assume future entity-system destructor support without changing this cleanup. 18. The hit average is now explicit, and a zero-area room probe is guarded before Sabine division. 19. Local sources use positive reference distance with zero rolloff.

## Remaining limitations

- When `sound_reload` replaces an OpenAL buffer still attached to an active source, OpenAL can reject deletion of the old buffer. The old buffer then remains until context teardown; implementing deferred retirement without cutting off a currently playing weapon sound is separate work. Upload failure no longer destroys the existing buffer.
- These tests use the actual bundled decoder and extracted production routines with fake AL; they cover mono/stereo/three-channel duration and mixing, EFX partial failures, rain failure, sticky-source bounds, and terrain-only probes. Syntax checks use real OpenAL Soft headers but no real audio backend or audible playback. No end-to-end HRTF, driver compatibility, sound-quality or frame-time measurement was possible.
- `sound_createEx` still runs immediate terrain occlusion probes on the main thread and room casts run each frame. No measured performance claim is made. Some malformed or extremely large WAVs are subject to the decoder's own allocation behavior before the uploader's size check.
